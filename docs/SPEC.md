# tekuteku 網上手作市集 — 規格（唯一真相來源）

> 2026-10-25 開，原名 DIY，2026-10 SS 把資料夾＋repo 改名 `tekuteku`。對外品牌見 §1（香港＝趁墟，日本＝てくてく市）。
> Cloudflare 資源（Worker／D1 `diy`、KV `DIY_PHOTOS`、網域 `diy.sssuni.com`）與 `~/.config/diy/` 都沿用舊名，不改。
> 狀態：2026-10-25 SS 已確認品牌、第一期範圍（香港先做、第一期就有申請頁）、repo 維持 public。2026-10-31 附加 Mail Club 構想（§11，排在第一期之後）。

## 0. 一句話

邀請手作人進駐的網上手作市集：訪客用自己的小人逛手繪市集街道，點攤位看手作人的作品，再連去他們自己的 IG／賣場買。先當「手作人資料庫」，之後讓攤主自己佈置攤位，最後才在站內真的賣。分**香港版**與**日本／沖繩版**。

SS 原話：「邀請 DIY 的手作人進駐，像一個網上手作市集但是可以用角色去逛的，店主可以自組佈置攤位，最終想要可以真正賣出的。參考他一開始只連 IG，像是一個手作資料庫，後面再連錢。」

## 2. 參考站研究：老闆不在・線上市集（2026-10-25 實測）

https://no-boss-here.pages.dev ——颱風天 5 小時做出、上線約 3 天已有 **2,182 攤**。

**玩法**
- 全台 22 縣市各一座手繪市集＋4 座主題市集（雲端市集＝沒實體店面、星語小巷＝命理、稻香站＝小農、舒活館＝美容按摩、師父在這＝教學）
- 每座市集多條「街」（例：手作區一街／共 17 條，每條 40 攤），拖小人走或點地面走
- 攤位＝遮雨棚（攤主選顏色）＋招牌＋6 字攤位牌＋3 件招牌商品＋價格；點開：照片、商品、攤主留言、「去賣場買」「看 IG」「送一朵花」「分享」「檢舉」
- 遊戲化：集章卡（逛 20/50/100 攤、去 3/10 座市集、發現在地動物）換衣服；扭蛋、籤筒、長椅等互動物件有隨機台詞；每縣市在地動物（藍鵲、石虎）；**真實天氣**（weather.json 標哪個縣市在下雨，市集就下雨）
- 線上人數、全台聊天室、攤位留言板（這些帶來大量管理工作：檢舉、黑名單、封 Gmail/IP、每日免費額度用完自動暫停）
- 頂部切換「逛街」／「品牌」（品牌牆＝格狀列表，給不想玩的人）

**資料結構**（`/data/index.json`，1.4MB，一次全載）
```json
{ "id": "<Firebase uid>", "name": "品牌名", "by": "攤主暱稱",
  "county": "taichung", "region": "central", "zone": "craft|food|wear|pick",
  "color": "#7fb0dc", "sign": "攤位牌(≤6字)", "note": "給客人的話",
  "items": [{"name": "...", "price": 170}], "photos": ["data/p/<id>-<hash>-0.jpg", ...],
  "igUrl": "...", "shopUrl": "...", "views": 1169,
  "approvedAt": "ISO", "v": "ISO(版本/快取)" }
```
**架構**：Google 登入（Firebase Auth）→ 申請寫進 Firestore → 核准後由後台**匯出成靜態 JSON＋照片複製到 `data/p/`**，訪客端只讀靜態檔（便宜、快、不怕流量）。

**審核**：一個 Google 帳號一攤；照片自動裁正方形縮圖；**自動上架條件**＝常見賣場網址（蝦皮/Pinkoi/IG…）＋沒敏感字＋至少一張照片；其他人工審；被退回或下架過的永遠人工審；有禁售清單（菸、藥、療效宣稱、仿冒、武器、成人、活體動物、賭博借貸投資等）。不經手交易，價格以賣場為準。

**我們學什麼、不學什麼**
- ✅ 學：訪客只讀靜態 JSON／攤主一人一攤／自動上架＋人工兜底／禁售清單／品牌牆給不想玩的人／空攤位「誠徵攤主」本身就是招商廣告
- ✅ 加碼（我們的差異）：**只收手作**（參考站 31% 是雲端代購雜貨）、**跨地區**（港＋日）、第二期攤主自己佈置、第三期真的能賣
- ❌ 第一期不做：聊天室、留言板（管理成本最大）、線上人數
- ❌ 不抄：手繪畫風、「老闆不在」用語、在地動物台詞

## 3. 分期

### 第一期：手作人資料庫＋可逛的市集＋自助申請（不碰錢）
- **香港、一座市集（深水埗）**先做透；資料結構從第一天就支援多地區，日本版之後只加設定檔＋美術
- 角色逛街：拖動／點地面走、鍵盤方向鍵、手機單指；角色可換膚色／髮型／衣服顏色（存 localStorage）
- 街道＋攤位：每條街一排排攤位；攤位顯示遮雨棚顏色、招牌、攤位牌、商品縮圖；**空攤位掛「誠徵攤主」→ 點了去申請**
- 攤位面板：3 張照片、品牌名、攤主暱稱、手作類別、3 件招牌商品＋價格（HKD）、給客人的話、**「看 IG」「去賣場」**按鈕、分享連結（`#stall=<id>` 深連結，打開直接走到該攤）
- 品牌牆：格狀列表＋類別篩選＋搜尋，給不想玩的人；跟逛街共用同一份資料
- 地標：深水埗 1–2 個街景地標（布行街、鈕扣舖）
- **「我要擺攤」申請頁**（§5）：填資料＋上傳 3 張照片 → 待審；送出後給一條**私人管理連結**（存起來，之後用它改資料或收攤），不需要帳號
- **審核後台**（只限 SS，Cloudflare Access＋登入紀錄）：待審清單、核准／退回（附原因）／下架
- 「關於」：不經手交易、價格以賣場為準、禁售清單、檢舉方式（email）
- 語言：繁中（香港書面語）＋英文切換
- **不做**：帳號登入、站內留言、聊天、收藏同步、金流、攤位佈置編輯器

**攤主自選（2026-10-31 定案）**：地圖上一攤約 100px 寬，只選遠看得到的東西。第一期申請表＝類別（決定攤位款式）、遮雨棚 8 色、攤位牌（≤6 字），再加小旗或吉祥物 6 選 1、燈色 3 選 1，都不需要帳號。陳列、擺設、攤主小人造型放第二期。**不開放上傳圖片到地圖上**（版權與畫風都難控制），作品照只放在攤位面板。

### 第二期：攤主自組佈置攤位
- 攤主帳號（Email magic link 或 Google 登入），取代第一期的私人管理連結（舊連結要能綁定到帳號）
- 攤位編輯器：選攤位型（推車／桌攤／小屋）、遮雨棚花色、招牌字、擺設道具（從道具庫拖到格子上：籃子、架子、盆栽、燈串、黑板…）、商品擺哪一格；即時預覽
- 自動上架規則（照參考站：常見賣場網址＋沒敏感字＋有照片；被退回過的永遠人工審）
- 日本版てくてく市上線（沖繩やちむん通り）
- 可能加：集章、送花（D1 匿名計數）

### 第三期：站內真的能賣
- 金流：**Stripe Connect**（香港、日本都支援；攤主自己完成 KYC，我們不碰錢包）
- 收費模式（待定）：抽成 5–10% ／ 月費（HK$48–98／¥980–1,980）／ 混合（免費攤抽成高、月費攤抽成低）
- 必要配套：庫存、訂單、運費、退換貨規則、客服責任歸屬
- **日本法規**：賣東西的攤主要有「特定商取引法に基づく表記」；平台本身要看是否構成「取引デジタルプラットフォーム」——第三期開工前要先查
- 食品類（自家烘焙等）在港日都牽涉牌照，第三期可能先排除食品

### 附加線：Mail Club 郵便局（§11）
不是第四期，也不是另一個平台。第一期完成後，先跑市場地圖，過門檻才開工；第三期的站內金流**不包含** Mail Club 訂閱。

### 4.1 分區主題包（2026-10-31 定案）
- **一區一張地圖**，上方分頁切換，手機只載入目前這區。可擴充：香港、日本、台灣；之後韓國、泰國、澳門
- 走路、碰撞、遮擋、點攤位、季節、燈光全部共用；**每區只換主題包**：地面、攤位外殼、建築、裝飾、配色
- 主題方向：香港＝唐樓、霓虹招牌、竹棚、鐵閘；日本＝木造屋台、暖簾、提燈、沖繩紅瓦；台灣＝夜市紅燈籠、騎樓、帆布棚；韓國＝布帳馬車；泰國＝陽傘攤；澳門＝葡式碎石路

- 順序：香港先接進遊戲並有真攤主，再開第二區，不同時開三區

- 攤位資料按地區分檔 `data/stalls/<region>.json`；每攤有 `region` + `market` + `street`
- 一個手作人可以同時在港、日各擺一攤（不同 id），第二期再處理帳號共用
- 介面字串放 `i18n/<lang>.json`，不要寫死在程式裡

## 5. 攤主申請與審核（第一期就做）

**流程**
1. 「我要擺攤」頁填表：品牌名（≤20）、攤主暱稱（≤12）、地區＋市集、手作類別（§5 類別表）、IG 網址（必填）、賣場網址（選填）、3 件招牌商品＋價格、給客人的話（≤40）、攤位牌（≤6）、遮雨棚顏色（8 色選）、**3 張自己拍的作品照**、聯絡 email（**不公開**）、兩個勾選：「是我自己做的作品／照片」「同意公開展示」
2. 照片**在瀏覽器端**裁成 800×800 正方形、轉 WebP（≤200KB）再上傳；Worker 端再檢查尺寸與格式
3. Cloudflare Turnstile 擋機器人；同一 email 只能有一攤（第一期）；同 IP 每小時最多 5 次申請
4. 送出 → 狀態 `pending`，畫面顯示**私人管理連結** `…/manage/#t=<token>`（只顯示一次，提醒存起來／加書籤）。token 只存 SHA-256 雜湊
5. SS 在後台審：是不是手作、照片是不是自己的、連結打得開、沒有禁售品 → 核准／退回（寫原因，攤主用管理連結看得到）
6. 核准 → 出現在市集與品牌牆（訪客端讀的 JSON 快取 ≤60 秒）
7. 攤主用管理連結改資料：改動存成「待審版本」，**已上架的舊版本照常顯示**，核准後才換；也可以「收攤」（刪資料＋刪照片，不可復原，要二次確認）
8. 第一期**全部人工審**（量少、安全）；第二期才加自動上架

**類別**（第一期）：飾物、布作／針織、皮革、陶瓷、木工、紙品／印刷、蠟燭／皂／香氛、插畫／藝術、手作食品、手作課程、其他手作

**禁售／不收**：非手作的代購轉售、仿冒品與侵權角色周邊（未授權卡通人物鉤織等）、菸酒、藥品與療效宣稱、成人用品、活體動物、武器。手作食品先收但標「請向攤主確認保存方式」。

**個資**：email 只存 D1，只有後台看得到；公開 API 絕不回傳 email、IP、token。申請時寫明「email 只用來聯絡審核結果」。

**檢舉**：攤位面板「檢舉」→ 第一期只是 mailto 連結到 SS 的檢舉信箱（不做站內檢舉系統）。

## 6. 技術

**前台**（GitHub Pages，`https://sssunwl.github.io/tekuteku/`）
- Vite + TypeScript，無框架；Canvas 2D 畫街景與角色，面板／品牌牆／申請頁用一般 DOM
- 訪客端只讀一個 JSON：`GET <API>/api/stalls?region=hk`（Worker 回傳、邊緣快取 60 秒）；API 掛了就退回 repo 內的 `data/demo/hk.json`（示範攤），市集照樣能逛
- 狀態：角色外觀、逛過哪幾攤 → localStorage（全部 try/catch）
- 手機優先；一條街只載這條街的照片（lazy）

**後端**（Cloudflare Worker `diy`，掛 `diy.sssuni.com`；之後有網域再換）
- D1 `diy`：表 `stalls`（id、region、market、status、`live_json`、`draft_json`、email、token_hash、created/updated/approved_at、reject_reason）、`visits`（登入紀錄）、`apply_log`（限流用）
- **照片存放：Workers KV**（namespace `DIY_PHOTOS`，key `p/<stallId>/<n>-<hash>.webp`）。原因：這個 Cloudflare 帳號**還沒開通 R2**（2026-10-25 實測 code 10042）。照片讀取走 Worker＋Cache API。若 SS 之後在 Dashboard 開通 R2，換成 R2 只改 `storage.ts` 一個檔
- 公開 API：`GET /api/stalls?region=`、`GET /p/<key>`、`POST /api/apply`（multipart）、`GET|PUT|DELETE /api/manage`（Bearer token）
- 後台：`/admin`（Worker 直接出 HTML）＋`/api/admin/*`，**Cloudflare Access 只限 SS 本人（email 用 secret `ADMIN_EMAIL` 設定，不寫進 repo）**，Worker 也要驗 `Cf-Access-Jwt-Assertion`（不能只靠 Access 擋）；照 `Knowledge/30_方法與SOP/登入紀錄/` 加登入紀錄，面板放 `/admin` 頁底
- CORS：只允許 `https://sssunwl.github.io` 和本機 dev 來源
- Turnstile secret、任何金鑰：用 `wrangler secret put`；本機副本放 `~/.config/diy/`，**絕不進 repo**
- 無追蹤碼；可加 Cloudflare Web Analytics（無 cookie）

## 7. 美術與版權

### 7.1 畫風（2026-10-26 SS 定案，第三次）
- 探索過程與全部試作：https://sssunwl.github.io/han/sucai/ （像素橫向街景 → 手繪水彩「很 AI」→ 日式簡約「太簡單看不到細節」→ 等角）

- **人物分兩種用途**：
  - **地圖上走動＝B 等角像素 Q 版**（`chars_pixel.png`）。調色要壓到場景的暖色調（2026-10-26 合成測試 `mix_check.png`：搭得起來，只是比場景亮）
  - **放大／對話時＝A 動漫 Q 版**（`chars_anime.png`）：選角色畫面、對話泡泡頭像、新手教學引導人
  - 同一個角色兩種版本要對得上（同髮色、同衣服）

### 7.2 素材怎麼來
- Codex 訂閱 image_generation，**每次都附 `scene_flat.png`（場景）或 `chars_pixel.png`／`chars_anime.png`（人物）當畫風參考**
- 生成時用**純洋紅 `#FF00FF` 底**，`tools/slice.py` 去背、裁邊、定腳底錨點，輸出 `public/art/*.webp` ＋ `public/art/manifest.json`
- **攤位跟類別走**：11 個類別各一款等角攤位（陶瓷攤擺陶杯、皮革攤擺銀包…）＋「誠徵攤主」空攤；第二期佈置再拆零件
- 人物：6 個可選角色，每個要等角「右下（正面斜）」「右上（背面斜）」各 idle＋走路 2 格，左邊方向用水平翻轉
- 介面：紙紋米白底、深棕細框，中文字型霞鶩文楷 TC（OFL）；介面也要跟場景同色系

## 11. Mail Club 郵便局（2026-10-31 附加，排在第一期之後）

### 11.1 定位
Mail Club＝創作者每月把信、版畫、貼紙等實體郵件寄給訂閱者。SS 不確定熱潮多久，所以**附在 tekuteku，不獨立成站**：退燒了只收掉一區，攤主資料和網站不受影響。

- 一句話：在市集裡開一間郵便局，讓人找到亞洲創作者的 Mail Club，看清楚這個月能不能訂、寄不寄得到自己家，再連去創作者原本的訂閱頁
- 品牌：「手紙」＝手＋紙，跟「てくてく」藏的「て（手）」同一條線
- 收錄範圍：亞洲優先（日本、台灣、香港先做），全球創作者也可申請
- 語言：繁中、日文、英文；日文要等第二期的多語言架構，郵便局不提前自建 i18n 系統

### 11.2 為什麼不做純名錄
名錄已有人做（2026-10-31 查，數字來自搜尋摘要）：MailClubly 約 1,166 個＋創作者營運工具、Mail Club Hub 約 248 個、Tiny Mail 約 89 個。比數量贏不了，差異只押三件事：

1. 亞洲創作者
2. 繁中＋日文
3. 能用小人逛，加上每月截單月曆

### 11.3 功能
- **郵便局主題區**：Mail Club 不屬於某個地點，所以不放進深水埗或やちむん通り，做成獨立主題區（跟街道同一套行走系統），每個 Mail Club 是一個小窗口
- **截單月曆**：這個月哪些 club 開放、幾號截止。這是讓人每月回來的理由，也當 IG／Threads 的固定內容
- **品牌牆**：可篩「Mail Club」，再按寄出地、可寄送國家、價格篩選
- **點開窗口**：照片、創作者介紹、每月價格、可寄送國家、開放狀態、「去訂閱」外連

### 11.4 資料
沿用 `stalls`，不開新表、不開新服務。攤位加 `type: "stall" | "mailclub"`，mailclub 多這些欄位：

```json
{ "type": "mailclub",
  "mailclub": { "priceMonthly": 12, "currency": "USD", "shipsFrom": "JP",
    "shipsTo": ["JP", "TW", "HK"], "shippingNote": "...",
    "status": "open|paused|closed", "opensOn": "YYYY-MM-DD", "closesOn": "YYYY-MM-DD",
    "subscribeUrl": "..." } }
```

- 訂閱連結必填，IG 改選填（有些 club 只放 Patreon／Carrd）
- `opensOn`／`closesOn` 過期就在前台標「日期待更新」，不顯示成開放中
- 創作者可標「暫停」；Mail Club 很耗體力，常有人中途停
- 價格以創作者訂閱頁為準，網站只顯示參考價

### 11.5 紅線
- **不爬資料**：只收本人申請或同意的 Mail Club，沿用 §5 審核；市場地圖名單只放 `_ref/` 或 repo 外，不公開
- 不經手訂閱款、不存訂閱者地址；Mail Club 訂閱**不併入**第三期金流，避開定期扣款、跨境退款與收件地址個資
- 不用 Next.js／Supabase／Vercel；沿用現有 Vite、Worker、D1、KV
- 公司登記與收款主體等開始收費才處理，現在不做

### 11.6 開工順序與門檻
先驗證，第一期完成前不寫程式。

1. **市場地圖（1–2 天，可與第一期並行）**：列日本、台灣、香港的活躍 Mail Club，記平台、價格、可寄送國家、最近一次寄出時間。「活躍」＝近 3 個月有寄出或開放訂閱
2. **判斷**：

| 找到的活躍亞洲 Mail Club | 下一步 |
|---|---|
| 30 個以上 | 開始邀請，目標 20 個同意刊登，再做 §11.3 |
| 不到 30 個 | 只在「紙品／印刷」加 Mail Club 標籤，不做郵便局和月曆 |

門檻是經驗值，可依地圖結果調整。

3. **上線後看 90 天**：創作者願不願意加入、訪客會不會點「去訂閱」、月曆有沒有帶來回訪或自然流量

**付費曝光**（首頁推薦、專題）等上述驗證通過才討論。
